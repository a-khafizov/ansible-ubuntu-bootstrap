# Как работает Ansible в этом проекте

## Общее описание

Ansible - это инструмент автоматизации конфигураций и управления инфраструктурой. В этом проекте он используется для автоматической настройки рабочей станции разработчика на Ubuntu.

## Структура проекта и взаимосвязи файлов

```
.
├── ansible.cfg              # Основной конфигурационный файл Ansible
├── inventory.ini           # Инвентарный файл (определяет управляемые хосты)
├── setup-workstation.yml   # Главный плейбук (точка входа)
├── group_vars/             # Глобальные переменные
│   └── all.yml            # Глобальные переменные для всех хостов
├── roles/                  # Каталог с ролями
│   ├── core/              # Роль для базовой настройки системы
│   │   └── tasks/main.yml # Задачи для роли core
│   ├── dev/               # Роль для настройки среды разработки
│   │   └── tasks/main.yml # Задачи для роли dev
│   └── vscode/            # Роль для установки и настройки VS Code через APT
│       └── tasks/main.yml # Задачи для роли vscode
├── scripts/                # Вспомогательные скрипты
│   └── bash/              # Bash скрипты
│       ├── setup_git.sh  # Настройка Git
│       └── setup_ssh.sh  # Генерация SSH-ключей
└── docs/                  # Документация
    └── ansible-explanation.md # Этот файл
```

## Основные компоненты

### 1. Конфигурационный файл (ansible.cfg)
Файл `ansible.cfg` - это основной конфигурационный файл Ansible, который определяет настройки по умолчанию:
- `inventory = inventory.ini` - указывает путь к инвентарному файлу
- `host_key_checking = False` - отключает проверку SSH ключей хостов

### 2. Инвентарный файл (inventory.ini)
Файл `inventory.ini` определяет управляемые хосты. В данном проекте:
```
[local]
localhost ansible_connection=local
```
Это означает, что мы настраиваем локальный хост с прямым подключением (без SSH).

### 3. Переменные (group_vars/all.yml)
Файл `group_vars/all.yml` содержит все глобальные переменные, которые используются в плейбуках:
- Флаги управления установкой компонентов (`install_core`, `install_dev_env`, `install_ide_config`)
- Пользовательские настройки (`username`, `user_home`, `git_username`, `git_email`)
- Списки пакетов для установки (`core_packages`)
- Настройки для VS Code (`vscode_extensions`)

### 4. Плейбук (setup-workstation.yml)
Файл `setup-workstation.yml` - это главный плейбук, который:
1. Определяет цель выполнения (localhost)
2. Подключает переменные из `group_vars/all.yml`
3. Выполняет предварительные задачи (создание директории ~/.local/bin)
4. Подключает роли в определенном порядке с условиями выполнения

### 5. Роли
Роли - это основные строительные блоки Ansible, которые содержат задачи для настройки определенных компонентов:

#### Роль core
Роль `core` отвечает за базовую настройку системы:
- Обновление списка пакетов
- Установка основных утилит из списка `core_packages`
- Установка DBeaver через Snap
- Добавление полезных алиасов в .bashrc

#### Роль dev
Роль `dev` отвечает за настройку среды разработки:
- Установка Python (pip, venv)
- Установка Node.js 20.x через NodeSource репозиторий
- Установка OpenJDK 17
- Установка Go 1.22.5 из официального архива
- Установка Docker через официальный репозиторий
- Установка kubectl v1.29.0 из официальной бинарной сборки
- Добавление ~/.local/bin в PATH

#### Роль vscode
Роль `vscode` отвечает за установку и настройку VS Code через APT:
- Добавление GPG-ключа Microsoft
- Добавление репозитория VS Code
- Установка VS Code
- Настройка конфигурации VS Code (settings.json)

### 6. Вспомогательные скрипты
Каталог `scripts/bash/` содержит вспомогательные скрипты:
- `setup_git.sh` - настройка Git с пользовательскими данными
- `setup_ssh.sh` - генерация SSH-ключей Ed25519

## Поток выполнения

1. Пользователь запускает плейбук командой:
   ```
   ansible-playbook -i inventory.ini setup-workstation.yml -K
   ```

2. Ansible читает конфигурационный файл `ansible.cfg`

3. Ansible загружает инвентарный файл `inventory.ini` и переменные из `group_vars/all.yml`

4. Ansible выполняет предварительные задачи (pre_tasks)

5. Ansible последовательно применяет роли в порядке их определения в плейбуке:
   - core
   - dev
   - vscode

6. Каждая роль выполняет свои задачи (tasks), определенные в файле `main.yml`

## Теги

Все задачи помечены тегами, что позволяет запускать только определенные части плейбука:
- `core` - базовая настройка системы
- `dev` - среда разработки
- `ide` - установка и настройка VS Code

Пример запуска только определенных тегов:
```
ansible-playbook -i inventory.ini setup-workstation.yml --tags "dev" -K
```

## Условия выполнения

Многие роли имеют условия выполнения, определяемые переменными из `group_vars/all.yml`:
- `when: install_core | bool` - роль core будет выполнена только если переменная `install_core` равна true
- `when: install_dev_env | bool` - роль dev будет выполнена только если переменная `install_dev_env` равна true
- `when: install_ide_config | bool` - роль vscode будет выполнена только если переменная `install_ide_config` равна true

Это позволяет гибко управлять тем, какие компоненты устанавливать.
